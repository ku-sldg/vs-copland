# vs-copland

Copland is a VS Code extension and language server that targets `.cop` files.  
It ships syntax highlighting powered by a TextMate grammar and syntax diagnostics generated by a custom lexer plus a tree-sitter parser.

## Features

- Syntax highlighting for Copland source files.
- Diagnostics for invalid identifiers, malformed constructs, and parse errors.
- Command palette entry `Copland: Run Copland Syntax Check` for manual validation.

## Repository Layout

```
.
├── client/                 # VS Code extension (language client + integration tests)
├── server/                 # Language Server (LSP implementation)
├── tree-sitter-copland/    # Tree-sitter grammar & native bindings
├── syntaxes/               # TextMate grammar
├── scripts/                # Test harness helpers
└── package.json            # Workspace scripts / metadata
```

## Prerequisites

- **Node.js 20 LTS or newer.** Some dependencies require Node 20+; Node 18 works but prints engine warnings.
- **npm 9+** (bundled with recent Node versions).
- **VS Code** (for debugging the extension and for supplying a VS Code binary during integration tests).
- **Build tools** needed by `node-gyp` (Python + compiler toolchain) if your platform does not already provide them. Tree-sitter native bindings are built during install.

## Setup & Build

1. **Install dependencies** (runs `npm install` in `client`, `server`, and `tree-sitter-copland` automatically):
   ```bash
   npm install
   ```
2. **Compile TypeScript sources**:
   ```bash
   npm run compile
   ```
   Use `npm run watch` for incremental builds during development.
3. **Lint** (optional but recommended before sending changes):
   ```bash
   npm run lint
   ```
   The ESLint config ignores generated tree-sitter sources.
4. **Debug in VS Code**:
   - Open this repository in VS Code.
   - Use the `Run Extension` launch configuration (F5) to start an Extension Development Host.

## Testing

Integration tests live in `client/src/test` and are executed with `@vscode/test-electron`.

```bash
npm test
```

The runner tries to download the required VS Code build. In restricted or offline environments:

- Set `VSCODE_EXECUTABLE_PATH` to point at an existing VS Code binary, e.g.
  ```bash
  VSCODE_EXECUTABLE_PATH=/usr/bin/code npm test
  ```
- If the variable is unset, the runner looks for `/usr/bin/code-insiders` and `/usr/bin/code` automatically.
- Without a local binary and without network access, the tests cannot run because VS Code cannot be acquired.

## Packaging & Installing the Extension

1. Ensure the project is compiled: `npm run compile`.
2. Create a VSIX (install `vsce` if necessary):
   ```bash
   npx vsce package
   ```
3. Install the generated `vs-copland-<version>.vsix` into VS Code:
   - Open the Extensions view (`Ctrl+Shift+X`).
   - Click the three-dot menu, choose **Install from VSIX...**, and select the VSIX file.
4. Open or create a `.cop` file to see highlighting and diagnostics.

## Functionality Notes

- Supported diagnostics focus on syntax issues today; semantic checks and tooling support are planned for future releases.
- Diagnostic handling runs both the lexer-based validations (invalid identifiers, improper null usage, etc.) and tree-sitter parse errors, then deduplicates results.

## Running the Sample Extension

1. Open this repository in VS Code.
2. Run `npm install` and `npm run compile`.
3. Press `F5` (or run the `Run Extension` launch config) to spawn a new VS Code window with the Copland extension loaded.
4. Create a `.cop` file and trigger `Copland: Run Copland Syntax Check` from the Command Palette.

## Troubleshooting

- **Engine warnings on install** – upgrade to Node 20+ to satisfy dependencies such as `glob@11`.
- **`node-gyp` failures** – ensure Python and a C/C++ compiler are available; see the [node-gyp docs](https://github.com/nodejs/node-gyp#installation) for platform-specific requirements.
- **VS Code download blocked during tests** – set `VSCODE_EXECUTABLE_PATH` to an existing VS Code binary as described above.
